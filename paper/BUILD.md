# Building the preprint PDF

This machine has no `pandoc`, no `xelatex`, and no `tectonic` (`where.exe` was empty on 22 August 2026). No TeX distribution was installed on it.

**Compiled twice**, in a container (path (c) below): `pdflatex` + `bibtex` + `pdflatex` x2 on `ghcr.io/xu-cheng/texlive-small`, exit 0, 15 pages, 0 undefined references or citations on both runs. Re-run it after any edit to `main.tex` or `refs.bib`.

- 23 August 2026 — first build. Its PDF carried `/Title()` and `/Author()`: an empty document information dictionary. It was not published.
- 24 August 2026 — the preamble names the title and the author once and `\hypersetup` reads them, so the dictionary is filled. Body unchanged: `\begin{document}` onward is byte-identical between the two trees, and `main.aux` is identical, so pagination and cross-references did not move.

`paper/arxiv/main.tex` was written by hand from `paper/two-ledgers-one-window.md`. It was not generated by pandoc.

## Correspondence (source vs tex)

Measured on the tree that carries this file:

- Markdown `##` headings map to LaTeX `\section`.
- Markdown `###` headings map to LaTeX `\subsection`.

Run, from the repository root:

```
# PowerShell
(Select-String -Path paper/two-ledgers-one-window.md -Pattern '^## ' -AllMatches).Count
(Select-String -Path paper/arxiv/main.tex -Pattern '\\section' -AllMatches).Count
(Select-String -Path paper/two-ledgers-one-window.md -Pattern '^### ' -AllMatches).Count
(Select-String -Path paper/arxiv/main.tex -Pattern '\\subsection' -AllMatches).Count
```

Those four numbers must pair: 11 sections with 11 sections, 3 subsections with 3 subsections. If they do not, the tex has drifted and is not a build of the markdown.

## Path (c) — container (no install on the host)

From the repository root, with Docker:

```
docker run --rm -e SOURCE_DATE_EPOCH=1787529600 -e FORCE_SOURCE_DATE=1 -v "$PWD/paper/arxiv:/src" -v "$PWD/paper/build:/out" -w /out   ghcr.io/xu-cheng/texlive-small@sha256:495075f44d717e3d801f1817eedfb95254e16789e5cb12d357f3c3938ccf9b9d   sh -c 'cp /src/main.tex /src/refs.bib . && pdflatex -interaction=nonstopmode -halt-on-error main.tex && bibtex main && pdflatex -interaction=nonstopmode -halt-on-error main.tex && pdflatex -interaction=nonstopmode -halt-on-error main.tex'
```

The image is pinned by digest, not by `:latest`. A tag moves; the build record below names a digest, and a command that does not name the same one cannot be said to have reproduced it.

`SOURCE_DATE_EPOCH` is the other half of that. Left unset, pdfTeX writes the wall clock into `/CreationDate` and `/ModDate`, and every rebuild produces a PDF with a different hash — so a reader comparing hashes cannot tell a changed clock from a changed paper. `1787529600` is 2026-08-24T00:00:00Z; it is recorded in the row below and must be passed as written. Measured: two container runs from the same commit, each into its own empty directory, produced the same PDF SHA-256.

Then check `paper/build/main.log` for `LaTeX Warning: Citation` / `Reference` lines; there should be none.

Then check that the PDF carries its own title and author:

```
node test/paper_pdf_metadata.mjs
```

That check also runs in `npm run test:checks`. Without a build present it can only measure the tex; the line it prints says which of the two it measured.

## Source tarball for arXiv

Built from `paper/build/` after the compile, so that `main.bbl` is the one the PDF used. The order of the three arguments is the order inside the archive.

```
cd paper/build
tar --format=ustar --owner=0 --group=0 --numeric-owner --mtime='@0' -cf source.tar main.tex refs.bib main.bbl
gzip -n -9 -c source.tar > two-ledgers-arxiv-source.tar.gz
rm source.tar
```

Owner, group and modification time are fixed, and `gzip -n` writes no timestamp of its own. Two runs of these two commands on the same three files produce the same bytes, so the tarball hash in the build record is a hash a reader can reproduce rather than one they must take on trust.

## Generated PDF

If a PDF is produced later, write it under `paper/build/` and nowhere else. That directory is gitignored. A generated PDF committed under `docs/` would enter the npm allow-list; `test/pack_tracked.mjs` is right to refuse a package built from files the repository does not describe.
