## Findings

### 1. src/http.ts — the first sentence a misconfigured operator reads

- Claim: the project ships a self-hosted gateway that a third party can run
  without us.
- Mechanism: `src/http.ts` refused to start without a token and said so in
  Turkish. The receipt viewer emitted `lang="tr"` and translated its labels
  through a presentation map; `public/` rendered its status text in Turkish;
  reasoning comments in `src/` were carried into `dist/` by the compiler.
- Why it falls short: the claim is about who can operate the thing. Operational
  text in a language the documentation does not use narrows that set without
  saying so, and the narrowing is invisible from the documentation, which was
  already English.
- Disposition: translated in d46b00d. Behaviour unchanged — strings, comments,
  `lang`, and a presentation map whose values became its keys.

### 2. No mechanism kept it out

- Claim: none stated; this is the absence behind finding 1.
- Mechanism: nothing read the packed file list for language. The text arrived
  over months, one comment at a time, and each addition was invisible.
- Disposition: `test/pack_locale.mjs` reads what `npm pack` would ship and fails
  on Turkish-specific letters outside a narrow allow-list. Shown failing before
  being wired in, and separately from a comment added to `src/http.ts` and
  carried into `dist/http.js` by a build — the path that produced the original
  text.

## Limits recorded rather than left to be found

- The check tests for Turkish letters, not Turkish language. A sentence written
  without them passes.
- Markdown that ships beside the code — changelog history, parts of `docs/` —
  is still Turkish in places. Second pass.
- The detector tokens, the record-kind name, and the sample names the locale
  tests pin are data rather than prose and were deliberately not translated.
